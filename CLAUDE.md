# CLAUDE.md: Screzy

Context for Claude Code (and other AI assistants) working in this repository.

## What this is

**Screzy**: *Scroll easy. Flick to coast. Steer with mouse or rollerbar.*
It is a Windows 10/11 system-tray utility that makes mouse-wheel scrolling smooth in every app. It adds acceleration, flick-to-coast momentum, and lets you steer a coast with the mouse or a Contour RollerMouse rollerbar.

- Publisher: **Eranno AS** (Norway). Licence: MIT. Website: https://screzy.com
- Microsoft Store listing name: **"Screzy – Easy, smooth scrolling"**, written with an en dash (–).
- The project was called **GlideScroll** during development. The only places that name may appear are `migrate_from_glidescroll()` and the old-ini path next to `iniPath` in `src/screzy.c`, plus the "Name" note in README and CHANGELOG. Don't "fix" those.

## Build

```sh
./build.sh            # Linux/macOS/WSL with mingw-w64
build.cmd             # Windows with w64devkit or MSYS2 (gcc + windres on PATH)
```

Flags: `-O2 -Wall -mwindows -static`, libs `-lwinmm -ldwmapi -lcomctl32 -lshlwapi -luser32 -lshell32 -ladvapi32 -lgdi32`. The build must stay warning-free.

## Architecture (read before changing scrolling code)

- **Mouse hook thread.** A `WH_MOUSE_LL` hook runs on its own `THREAD_PRIORITY_TIME_CRITICAL` thread with its own message loop. `WM_MOUSEMOVE` returns immediately (the fast path) unless a coast is running *and* steering is on. Never add work, locks, logging or allocation to that path: it makes the pointer feel "mushy" system-wide.
- **Wheel handling.** Only real notched clicks (multiples of 120) are swallowed. Touchpads and high-resolution wheels, Ctrl/Alt/Win + wheel, horizontal wheel, and elevated target windows are passed through untouched.
- **Animation thread.** A critically damped spring (ω = 4.74 / duration) moves toward a target. Frames are paced to the monitor refresh rate (`DwmGetCompositionTimingInfo` plus a high-resolution waitable timer, mid-frame). A **minimum step floor** (≈ 360 / Windows lines-per-click × dt) keeps the end of a glide even. Its sub-unit carry must be kept while coasting.
- **Coasting.** A flick is detected when the smoothed click rate is at least `flick_rate` *and* the fast run is at least `flick_clicks`. A coast decays exponentially unless steered. Steering (wheel, *Push* or *Distance from start*) sets and holds the speed. A mouse click stops a coast and is swallowed **together with its button-up**. The opposite wheel click slows the coast (or stops it, as an option).
- **Ready state.** A flick can wait (`Wait (ready)`), or Alt+middle click / Alt+G (`RegisterHotKey`) can enter it directly. Alt+middle uses the menu-mask trick (vk 0xE8) so Alt doesn't open menus.
- **Indicator.** A layered window (`WS_EX_TRANSPARENT|TOPMOST|NOACTIVATE|TOOLWINDOW`). Call `UpdateLayeredWindow` **only when its state or position changes**: redrawing every frame caused choppy scrolling.
- **Tray.** The main window is a hidden top-level `WS_POPUP` with `WS_EX_TOOLWINDOW`, not message-only, so it receives `TaskbarCreated` and re-adds the icon after Explorer restarts. Single instance: mutex `Screzy_SingleInstance`. A second launch opens Preferences in the first instance (found with `FindWindowA("ScrezyWnd")`).
- **Packaged vs. unpackaged.** `is_packaged()` uses `GetCurrentPackageFullName`. The Store build uses the `StartupTask` (`ScrezyStartup`) and opens `ms-settings:startupapps`. The plain exe uses the `HKCU\…\Run` value `Screzy`.
- **Settings.** INI file `%APPDATA%\Screzy\screzy.ini`, section `[general]` plus per-app rules (`exe=distance multiplier` or `off`). On first start, `glidescroll.ini` is copied over once.

## Invariants: don't break these

1. **Privacy promises** (`PRIVACY.md`, `website/privacy/`, Store listing): no network access, no telemetry, **no keyboard hook**, nothing logged or stored except the INI file. Any feature that touches new input or data must update all three privacy texts and the Store reviewer notes in `store/README.md`.
2. **Control IDs.** Sliders use `ID_TB0` 400–439, their value labels `ID_VAL0` 440–479, and other controls 220–234. Menu commands are 1001–1009. `NTB` is the slider count, and a typedef size guard checks that the ranges can't collide. Keep new IDs out of those ranges.
3. **DPI.** The process is system-DPI aware. Every pixel in the Preferences layout goes through `S()`. Test at 100%, 125% and 150%: labels have been clipped before.
4. **Version.** When releasing, bump `APP_VERSION` in `src/screzy.c`, `FILEVERSION`/`PRODUCTVERSION` and the strings in `res/screzy.rc`, `CHANGELOG.md`, and pass `-Version x.y.z.0` to `store/pack.ps1`. The Store requires the 4th part to be `0`.
5. **Docs stay in sync.** A change to settings, defaults or behaviour must also update `README.md` (Settings table), `CHANGELOG.md`, `store/README.md` (listing and reviewer notes), `website/index.html` where relevant, and `docs/preferences.png` if the window changed.
6. **Anything under `website/` is public on push** (Cloudflare Pages redeploys it). Only finished files that something references go in `website/`, `store/` or `res/`. Drafts, exports and AI generations stay in `inbox/`.
7. **Recommended Windows setting** is *Lines to scroll at a time = 1* (3 as the alternative). Keep that consistent everywhere.

## Testing

- No automated test suite. Manual checks on real Windows with a notched wheel:
  - browser
  - VS Code / Antigravity
  - Word or PDF reader
  - Explorer
  - per-app *Disable smoothing*
  - coast and stop-click (the click must not reach the page)
  - steering in both modes
  - Ready shortcut
  - tray after `taskkill /f /im explorer.exe` and restart
  - 125% scaling
- On Linux, Wine plus Xvfb can smoke-test startup and the Preferences UI. Caveats:
  - Wine doesn't hold the pointer for *Push* steering.
  - Wine windows are often elevated, so smoothing is bypassed.
  - A process started within 90 s of Explorer is treated as autostart (no Preferences window), so launch it twice.
- For timing diagnostics, add temporary logging behind `#ifdef GS_DEBUG` (writes `C:\gs.log`), and never ship it.

## Style

- C99, 4-space indent, `static` everything, short helper functions, ANSI (`A`) Win32 APIs.
- User-facing text: plain, friendly English. Sentence case. No jargon in Preferences.
- Commit messages: imperative summary line under 70 characters.
